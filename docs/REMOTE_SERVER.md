# سيرفر C++ باستخدام scrcpy وADB

يعمل `k230-server` كعملية تحليل Linux دون واجهة رسومية. يستخدم تنفيذ
`k230-monitor` نفسه: اتصال ADB مصرح، تشغيل scrcpy-server 4.0 المثبت على
الهاتف، استقبال H.264 والصوت، ثم YOLO وNSFWJS وسياسة العمر وCompanion v2.
لا يستخدم تطبيق الطفل MediaProjection، ولا توجد خدمة رفع PNG منفصلة.

## حزمة التشغيل الجاهزة

الحزمة المرفقة مخصصة لـ **Ubuntu 22.04 x86-64** وتحتوي:

- `bin/k230-server` و`bin/adb`.
- `assets/scrcpy-server` المثبت ببصمة SHA-256، والنموذجين.
- مكتبة ONNX Runtime ودليل التشغيل وبرنامج التشغيل المساعد.

ثبّت مكتبات النظام عند الحاجة:

```sh
sudo apt-get install libavcodec58 libavutil56 libswscale5
```

بعد فك الحزمة، ادخل مجلد `k230-adb-server-ubuntu22`:

```sh
./bin/adb version
sh tools/run_adb_server.sh --help
```

## تجهيز اتصال الهاتف البعيد

1. ثبّت APK على هاتف الوليّ وهاتف الطفل، وأكمل الاقتران وسياسة العمر
   وإذن إمكانية الوصول. اقتران التطبيق مختلف عن اقتران ADB.
2. فعّل خيارات المطور والتصحيح اللاسلكي على هاتف Android 11 أو أحدث.
   أبق الهاتف على شبكة Wi-Fi تسمح بالتصحيح اللاسلكي.
3. جهّز مسار شبكة خاص من السيرفر إلى الهاتف، مثل VPN يدعم الوصول إلى
   منفذي الاقتران والاتصال الفعليين. وجود VPN وحده لا يثبت وصول ADB؛
   اختبر ذلك على الهاتف. لا تنشر منافذ ADB أو 5037 على الإنترنت العام.
4. افتح «الاقتران باستخدام رمز» في إعدادات التصحيح اللاسلكي، ثم على السيرفر:

```sh
PHONE_HOST=100.64.0.2
PAIR_PORT=37111
CONNECT_PORT=37123
./bin/adb pair "$PHONE_HOST:$PAIR_PORT"
```

الأرقام مثال فقط: استخدم العنوان القابل للوصول والمنفذين الظاهرين على
هاتفك. أدخل رمز الاقتران عندما يطلبه ADB؛ لا ترسله في المحادثة أو Git.
منفذ الاقتران يختلف عن منفذ الاتصال، وقد يتغير منفذ الاتصال لاحقاً.

## بدء التحليل والحماية

```sh
sh tools/run_adb_server.sh --connect "$PHONE_HOST:$CONNECT_PORT" --max-fps 10
```

يتصل البرنامج بـADB ويتحقق من أن حالة **ذلك الهاتف نفسه** `device` قبل
بدء scrcpy. إذا كان الهاتف متصلاً بالفعل، يمكن تحديد `--serial`:

```sh
sh tools/run_adb_server.sh --serial "$PHONE_HOST:$CONNECT_PORT" --max-fps 10
```

تعمل العملية ما دام الاتصال قائماً. للإيقاف اضغط Ctrl+C. لا يلزم تشغيل
واجهة ويب أو قبول إذن مشاركة شاشة MediaProjection في التطبيق.
لتجربة USB محلية استخدم رقم الهاتف من `./bin/adb devices` مع `--serial`.

## الصور والصوت والقرارات

الهاتف يرسل الفيديو المضغوط والصوت عبر قناة scrcpy داخل اتصال ADB. يفك
السيرفر الفيديو ويحلل الإطارات مع الاحتفاظ بـPTS الأصلي. لا يلزم تحويل
الإطار إلى PNG قبل نقله؛ خيارات التشخيص السابقة تستطيع حفظ PNG والصوت
إذا فعّلتها عمداً. التشغيل أعلاه لا يفعّل `--record` أو `--dump-dir`.

تحديد المناطق والتصنيف وسياسة العمر تتم في C++. التغطية والحاجب وHOME
تنفذ في تطبيق الطفل عبر Companion v2 المُمرر بوساطة ADB. ربط الساعة،
هوية الشاشة، انتهاء القرار بعد 750ms وACK التنفيذ تبقى كما في المسار
الأصلي. بطء الشبكة قد يجعل القرار قديماً فيُرفض؛ لا نخفف هذه الشروط.

الصوت يستخدم `audio_source=playback` و`audio_dup=true` لإبقائه مسموعاً
على الهاتف، وهذا المسار يحتاج Android 13 أو أحدث، وقد يمنع التطبيق
المصدر التقاطه. على هاتف أقدم أو إذا فشل التقاط الصوت، أضف `--no-audio`
لتشغيل الفيديو والتحليل والحجب فقط.

## الحدود والتفعيل

- تشغيل التطبيق وحده لا يفعّل التصحيح اللاسلكي ولا يقترن بـADB تلقائياً.
- هذا عامل تحليل لهاتف واحد؛ المنافذ المحلية ثابتة، فلا تشغّل عدة نسخ
  على المضيف نفسه دون عزلها. ليس HTTP API أو لوحة ويب.
- لا يوجد اتصال تلقائي متجدد بعد انقطاع الجلسة؛ حدّث المنفذ وأعد التشغيل.
- الصور والصوت تصل إلى السيرفر عبر scrcpy. تنبيهات الوليّ تحمل البيانات
  الوصفية المشفرة فقط، وتحتاج Firebase الإنتاجي للتوصيل البعيد.
- حالة الشبكة الخاصة واقتران ADB وscrcpy والحجب على هاتف حقيقي لم تختبر
  لهذه الحزمة داخل هذه البيئة. فحوص البناء والوحدات لا تستبدل ذلك.

## البناء من المصدر

```sh
cmake -S . -B build -G Ninja -DK230_TARGET=pc -DK230_ENABLE_ONNX=ON \
  -DONNXRUNTIME_ROOT="$PWD/output/onnxruntime"
cmake --build build -j4
sh tools/run_adb_server.sh --connect "$PHONE_HOST:$CONNECT_PORT" --max-fps 10
```

جهّز ONNX Runtime حسب README. يمكن تحديد `K230_SERVER_BINARY` لمسار بناء
مختلف، و`ADB` لمسار عميل ADB. تظل أهداف monitor وK230 السابقة موجودة.
